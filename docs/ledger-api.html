Ledger API: проверяем не только ответ, но и базу

Ledger API: checking the database, not just the answer

Публичное API не пускает внутрь базы, поэтому я написал своё — сервис кошельков и переводов на PostgreSQL. 47 тестов сверяют каждый ответ с тем, что реально лежит в таблицах. Каждый прогон получает новую базу от Testcontainers.

A public API never lets you into its database, so this is our own: a wallets-and-transfers service on PostgreSQL. 47 tests compare every answer with what is actually in the tables, and every run gets a brand-new database from Testcontainers.

Базы не пересекаются, поэтому тест может проверять точное число строк. Без Docker тесты локально пропускаются, а в CI падают.

The databases never overlap, so a test can assert exact row counts. Without Docker the tests are skipped locally and fail in CI.

ГонкаThe race

25 параллельных переводов по 10 со счёта, где 100

25 parallel transfers of 10 from an account holding 100

Все запросы приходят одновременно. Блокировка строки SELECT … FOR UPDATE выстраивает их в очередь: ровно 10 проходят, 15 получают 422, баланс ровно 0.00. Без блокировки этот тест падает.

All requests arrive at once. The row lock SELECT … FOR UPDATE queues them: exactly 10 succeed, 15 get 422, the balance is exactly 0.00. Without the lock this test fails.

Ловят ли тесты баги?Do the tests catch bugs?

Пять багов, внесённых руками, — пять пойманных

Five planted bugs, five caught

Каждый баг вносился в сервис, затем гонялись тесты против настоящего PostgreSQL, и изменение откатывалось. Это ручная форма мутационного тестирования.

Each bug went into the service, the suite ran against a real PostgreSQL, and the change was reverted: a manual form of mutation testing.

Защита в глубинуDefence in depth

Схема сама не даст сохранить плохие данные

The schema itself refuses bad data

Тесты пишут в базу напрямую, в обход API, и ждут отказа ограничения. Даже если в коде появится баг, деньги не уйдут в минус.

The tests write to the database directly, bypassing the API, and expect a constraint to refuse. Even with a code bug, money cannot go negative.
